# using-AI 允许公开的使用效果评估记录

本文件只保存符合披露要求的通用指标和经验，不承担公司业务项目的原始任务档案功能。原始 TASK、需求、代码、数据库、测试、返工和人工介入证据保留在业务项目或公司批准的存储位置，不自动同步到此处。

## 披露边界

任务记录和五项评估口径以 [develop.md 的“业务任务追踪”](develop.md#业务任务追踪) 为唯一来源；导出与公开遵循其[数据安全边界](develop.md#数据安全与记录边界)。内部允许记录不代表允许公开，用户要求汇总也不等于取得公司披露授权。统计及 Token、费用同样需要符合公司规定；匿名化仍须考虑组合信息重新识别风险。无法确认时不导出，不为评估额外扫描业务项目或要求导出公司资料。

公开条目仅包含获准披露的最小必要内容：模型与 Agent、首次交付、返工、人工介入、Token 与费用及可公开的证据边界。不得复制内部任务 ID、业务提交号、路径、原始日志或报告链接作为公开证据。五项信息可在原 TASK 中完整保留，不能公开的部分不转存到此处。

缺失项使用 UNKNOWN 或“未记录 / 不可测量”，不等于零、失败或未发生。汇总比较须说明可用样本、统计口径、观察范围和缺失项；不将局部计数当作任务全量，不推算未测量的成功率、返工率、成本或收益，不为案例完整性补造数据。

## 可公开的通用经验

- Git 提交作者和提交顺序不能独立证明具体 Skill 调用、模型身份或返工原因。
- 首次交付与后续修复分别保留证据，不用最终结果倒推首次成功，不将新增需求自动归为返工。
- 静态检查、模拟、实际运行及真实业务验收分别说明；修复前的测试不能冒充修复后复验。
- 没有同条件基线和完整测量时，不宣称 Token、费用或人工时间节省比例。
