# 变量填写示例

以一个虚构的「订单管理」模块为例，演示模板变量的完整取值与产出物目录结构。
把下表的取值全局替换进 `claude研发流水线提示词模板.md` 或 `codex研发流水线提示词模板.md` 即可直接使用。

---

## 一、变量取值

| 变量 | 取值 |
|------|------|
| `{{PROJECT}}` | 示例商城 |
| `{{MODULE}}` | 订单管理 |
| `{{MODULE_SLUG}}` | order-management |
| `{{VERSION}}` | v1 |
| `{{REQ_DOCS}}` | docs/需求/order-management/表设计.md<br>docs/需求/order-management/页面逻辑.md |
| `{{DESIGN_DOCS}}` | docs/design/order-list.html |
| `{{QA_DIR}}` | docs/qa/order-management/v1 |
| `{{SPEC_FILE}}` | specs/order-management-v1.md |
| `{{REVIEW_DIR}}` | docs/review |
| `{{CHANGE_NAME}}` | order-management-v1 |
| `{{CHANGE_DIR}}` | openspec/changes/order-management-v1 |
| `{{TASK_PREFIX}}` | OM |
| `{{BACKEND_LAYERS}}` | 数据库/DDL → Entity/DTO → 数据访问层 → 业务逻辑层 → 接口层 |
| `{{FRONTEND_LAYERS}}` | API 定义 → 表单与列表组件 → 页面与路由集成 |

> 多条路径的变量（`{{REQ_DOCS}}` / `{{DESIGN_DOCS}}`）替换时按行罗列即可；用不到的直接删除该行。

### 阶段2 产出：`specs/order-management-v1.md` 第9章

```markdown
## 9. 假设与待确认列表

- 【假设ID】：ASSUM-001（关联历史问题 ID：PD-002）
- 【内容】：已发货订单的退款需先完成退货入库
- 【影响范围】：订单状态机、库存服务、退款服务
- 【默认行为】：未确认前，已发货订单点击退款仅创建「待退货」单据，不触发实际退款
- 【后续确认建议】：与业务方确认财务对账口径后升级为确定性逻辑
```

## 四、执行节奏参考

| 轮次 | 动作 |
|------|------|
| 第 1 轮 | 粘贴阶段1 Prompt → AI 输出 QA → **人工逐条填写【关闭原因】或【人工追问记录】** |
| 第 2 轮 | 再次粘贴阶段1 Prompt（增量更新）→ 直到关键问题全部 `✅ 已关闭` |
| 第 3 轮 | 粘贴阶段2 → Review Spec 的数据结构与接口 |
| 第 4~5 轮 | 阶段3、阶段4 → Review 提案与任务拆解 |
| 第 6~N 轮 | 阶段5，一次一个 task；遇 ⚠️ 阻断则先回头闭环假设 |
| 收尾 | 阶段6 → Review 用例后自动推演；阶段7 → 审计并归档 |
